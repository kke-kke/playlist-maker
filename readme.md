# Проект Яндекс.Практикум по курсу "Android-разработчик"

Данный проект - учебный проект Яндекс.Практикум по курсу "Android-разработчик", разрабатывался на протяжении части курса с android-разработкой.

# Техническое задание

Проект представляет собой небольшое приложение создания плейлистов, использующее [API iTunes](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/Searching.html#//apple_ref/doc/uid/TP40017632-CH5-SW1). Приложение предоставляет следующую функциональность:

- Поиск треков;
- Встроенный плеер с деталями трека;
- Проигрывание рандомного 30-секундного отрывка песни во встроенном плеере;
- Добавление треков в "Избранное";
- Составление и редактирование плейлистов;
- Переключение светлой/темной темы.

# Общие требования

Навигация осуществляется с помощью BottomNavigationView.
Когда на экране видна клавиатура, панель навигации скрыта за ней.
Экран «Медиатека» является главным.
Когда приложение запущено и пользователь находится на главном экране, пользователь видит нижнюю панель навигации с элементами «Медиатека», «Поиск» и «Настройки».
Если в этот момент выбран элемент «Медиатека», то пользователь видит этот элемент в выбранном состоянии, а все остальные в невыбранном состоянии (и т.д.).
Обратная навигация для экрана трека (при нажатии на аппаратную кнопку "Back" и на кнопку «Назад» в Toolbar) работает одинаково и убирает экран из BackStack.

## Главный экран -- экран Медиатека

На этом экране есть TabLayout с двумя экранами - Избранные треки и Плейлисты.

### Особенности экрана Избранные треки

Чтобы трек был добавлен в избранное, пользователь должен нажать на кнопку «Нравится» с изображением сердечка на экране «Аудиоплеер».
После нажатия на неё или в случае, если трек уже был добавлен в избранное, эта кнопка должна быть подсвечена (кнопка находится в выделенном состоянии).
При нажатии на кнопку в подсвеченном состоянии трек удаляется из избранного.
Последние треки, добавленные в избранное, должны находиться в верхней части списка.
Нажатие на элемент списка должно перенаправлять пользователя на экран соответствующего трека.
Если список избранных треков пуст, то на этом экране должна показываться заглушка "Ваша медиатека пуста".

### Особенности экрана Плейлисты

Есть кнопка "Новый плейлист". Под ней отображаются плейлисты либо заглушка.
Если не создано ни одного плейлиста, отображается заглушка "Вы не создали ни одного плейлиста".
Если плейлисты есть, они отображаются в списке в две колонке в виде - обложка плейлиста (или заглушка), название плейлиста, количество треков в плейлисте.

### Особенности экранов Новый плейлист, Добавить в плейлист (всплывающее окно)

Переход к экрану "Новый плейлист" осуществляется при нажатии на кнопку "Новый плейлист" на экране "Плейлисты" или на всплывающем окне экрана "Аудиоплеер".
Кнопка «Создать» на экране создания плейлиста неактивна, если не заполнено поле «Название».
При нажатии на область для отображения обложки пользователь должен иметь возможность выбрать любое изображение из имеющихся на его устройстве. Здесь доступен выбор из галереи, Google Photos или других доступных изображений. Если изображение выбрано, то оно должно отображаться в области для обложки.
Нажатие на кнопку «Назад», системную Back и аналогичный жест должны закрывать экран создания плейлиста и возвращать пользователя на предыдущий экран.
Если в момент закрытия пользователь уже добавил обложку, ввёл название или описание, то пользователю должен показаться диалог с заголовком «Завершить создание плейлиста?», сообщением «Все несохраненные данные будут потеряны» и двумя кнопками: «Отмена» и «Завершить».
Нажатие на кнопку «Отмена» закрывает диалог, и пользователь остаётся на экране создания плейлиста. При нажатии на кнопку «Завершить» диалог исчезает, экран создания плейлиста закрывается и пользователь возвращается на предыдущий экран.
Если кнопка «Создать» активна, то при нажатии на неё экран создания плейлиста закрывается, и пользователь возвращается на предыдущий экран. Пользователь также должен увидеть всплывающее сообщение об успешном создании плейлиста в формате: «Плейлист [название плейлиста] создан».
После успешного создания плейлиста файл изображения обложки должен быть доступен для приложения, даже если пользователь удалит оригинал изображения.

Находясь на экране «Аудиоплеер», при нажатии на кнопку «Добавить в плейлист» пользователь должен увидеть всплывающее окно со списком созданных плейлистов и кнопкой «Новый плейлист».
При нажатии на элемент списка:
- Если трека с таким идентификатором нет в плейлисте, на который нажал пользователь, то список плейлистов скрывается, трек добавляется в плейлист и пользователю показывается всплывающее сообщение с текстом в формате «Добавлено в плейлист [название плейлиста]».
- Если трек с таким идентификатором уже есть в плейлисте, на который нажал пользователь, то трек не добавляется в плейлист и пользователь должен увидеть всплывающее сообщение с текстом формата «Трек уже добавлен в плейлист [название плейлиста]».
При нажатии на кнопку «Новый плейлист» пользователь должен быть перенаправлен на экран создания плейлиста. В этом случае после закрытия экрана создания плейлиста и после успешного создания пользователь должен вернуться на экран «Аудиоплеер».

### Особенности экрана Плейлист

Экран для просмотра информации о плейлисте - обложка (или заглушка), название плейлиста, описание плейлиста (если есть), общая продолжительность треков в плейлисте, количество треков, кнопка "Поделиться", кнопка "Меню", полный список треков.
Пользователь может растянуть список треков на весь экран (поведение как с Bottom Sheet), при этом не может скрыть этот список с экрана.
При нажатии на элемент списка треков пользователь должен быть перенаправлен на экран «Аудиоплеер», где он может прослушать отрывок выбранного трека.
При длительном нажатии на элемент списка пользователь видит диалог с заголовком «Удалить трек», сообщением «Вы уверены, что хотите удалить трек из плейлиста?» и кнопками «Отмена» и «Удалить». При нажатии на кнопку «Отмена» диалог просто закрывается. При нажатии на кнопку «Удалить» диалог закрывается, трек, в отношении которого был вызван диалог, удаляется из плейлиста и пропадает из списка треков.
Если в плейлист не было добавлено ни одного трека, то при нажатии на кнопку «Поделиться» пользователь видит всплывающее сообщение - «В этом плейлисте нет списка треков, которым можно поделиться».
Если в плейлист был добавлен хотя бы один трек, то при нажатии на кнопку «Поделиться» пользователь видит диалог для отправки сообщения с использованием приложений, доступных на устройстве.
Сообщение для получателя должно содержать простой текст со списком треков плейлиста с названием плейлиста, описанием на следующей строке, количеством треков в формате «[xx] треков», где «[xx]» — количество треков на следующей строке, пронумерованным списком треков плейлиста в формате: «[номер]. [имя исполнителя] - [название трека] ([продолжительность трека])».
Каждый трек отображается в отдельной строке.
При нажатии на кнопку «Меню» (три точки) пользователь должен видеть всплывающее меню (Bottom Sheet) с краткой информацией о текущем плейлисте и списком дополнительных возможностей.
Пользователь может жестом скрыть меню с экрана.
Нажатие на пункт «Поделиться» в списке меню работает аналогично нажатию на кнопку «Поделиться» на экране плейлиста.
При нажатии на пункт «Удалить плейлист» всплывающее меню исчезает и пользователь видит диалог подтверждения с заголовком «Удалить плейлист», текстом «Хотите удалить плейлист?» и кнопками «Нет» и «Да».
При нажатии на кнопку «Нет» диалог закрывается и пользователь остаётся на экране плейлиста. При нажатии на кнопку «Да» текущий плейлист со всей информацией о добавленных в него треках удаляется, пользователь возвращается на экран «Медиатека» и больше не должен видеть удалённый плейлист в разделе «Плейлисты».

### Особенности экрана Редактировать плейлист

При входе на этот экран все поля и обложка должны быть заполнены информацией плейлиста, с которого был осуществлён переход.
Пользователь может редактировать все поля точно так же, как и на экране создания плейлиста.
Кнопка «Сохранить» находится в активном состоянии, только если поле «Название» непустое. В противном случае кнопка должна находиться в неактивном состоянии.
Если пользователь внёс какие-то изменения в информацию о плейлисте и поле «Название» непустое, то при нажатии на кнопку «Сохранить» экран редактирования закрывается, пользователь возвращается на экран плейлиста и видит все внесённые изменения.
При нажатии на кнопку «Назад» на экране, на системную кнопку Back или при выполнении соответствующего жеста экран редактирования закрывается, пользователь возвращается на экран плейлиста и все внесённые изменения игнорируются.
Сохранить изменения можно только нажатием на кнопку «Сохранить».

## Экран Поиск

Если пользователь находится в процессе ввода поискового запроса на экране «Поиск», то всякий раз, когда с момента ввода последнего символа запроса проходит больше двух секунд, приложение выполняет API-запрос с текстом, который находится в этот момент в поле ввода.
С момента выполнения запроса до того, как приложение получит ответ от сервера, на экране «Поиск» отображается индикатор загрузки.
Если поисковый API запрос завершился неудачно, отображается заглушка "Проблемы со связью" и кнопка "Обновить", которая повторяет последний поисковой запрос.
Если в результате успешного выполнения поискового API запроса не было найдено ни одной аудиозаписи, то на экране «Поиск» отображается заглушка "Ничего не нашлось".
Когда от сервера получен не пустой результат поискового запроса, то на экране «Поиск» отображается список треков, и пользователь видит элементы списка, каждый из которых имеет:
- область для отображения обложки (обложка или плейсхолдер),
- название трека,
- имя исполнителя,
- продолжительность трека в формате mm:ss.

### Особенности экрана

Если пользователь находится на экране «Поиск», поисковый запрос непустой, на экране отображается список треков, и пользователь видит кнопку «Очистить поисковый запрос» в поле ввода поискового запроса, то при нажатии на эту кнопку поисковый запрос очищается, клавиатура прячется, а кнопка (x) и список треков исчезают.

История поиска - хранение 10 последних треков, на которые переходил пользователь из списка результатов.
Треки хранятся в истории в порядке добавления (новые отображаются в верхней части списка).
Если трек, на который нажал пользователь, уже есть в истории, то он должен оказаться в верхней части списка, а предыдущая запись об этом треке должна быть удалена.
Нажатие на кнопку «Очистить историю» полностью очищает записи истории поиска.

## Экран Аудиоплеер

На экране отображается подробная информация о треке: обложка альбома (или заглушка), название трека, исполнитель, длительность, альбом, год, жанр, страна.
Есть кнопки: добавить в плейлист, плей, добавить в избранное.
При нажатии на кнопку "Добавить в плейлист" появляется всплывающее окно с плейлистами.
При нажатии на кнопку проигрывания изображение на ней сменяется на кнопку паузы. Пока отрывок проигрывается, показывается прогресс в формате mm:ss. Когда отрывок закончился, или пользователь нажал на кнопку проигрывания, изображение сменяется на кнопку плей.
При нажатии на кнопку "Добавить в избранное" поведение как в п. Особенности экрана Избранные треки.

## Экран Настройки

На экране находятся следующие пункты настроек: переключатель темной темы, поделиться приложением, написать в поддержку, пользовательское соглашение.
При нажатии на кнопку «Поделиться приложением» появляется диалог для шаринга сообщения в любой из доступных мессенджеров на устройстве. Текст сообщения содержит ссылку на курс по Андроид-разработке в Практикуме.
При нажатии на кнопку «Написать разработчикам» открывается почтовый клиент по умолчанию (или пользователю предлагается выбрать почтовый клиент из имеющихся на устройстве). В почтовом клиенте предзаполнены поля Кому (To) / Тема (Subject) / И текст письма.
При нажатии на кнопку «Пользовательское соглашение» открывается браузер по умолчанию (или пользователю предлагается выбрать из браузеров, установленных на устройстве). В браузере открывается ссылка на оферту из задания.
Приложение сохраняет текущую настройку темы (светлая/тёмная) в SharedPreferences. Тема приложения загружается из SharedPreferences при каждом запуске.
